Восемь правил, на которых держится цепочка

Эти правила определяют, как агенты соединены и что им разрешено. Если решение противоречит правилу, пересматриваем решение.

Приватность стоит первой
Ни один агент не получает сырые кадры и физиологию в обход A2. Данные, не прошедшие политику, для остальной цепочки не существуют. При сбое политики поток закрывается (fail-closed).
Два контура
Контур безопасности (A4 → A8 → A13 и A9 → A13) детерминирован, без LLM, с предсказуемой задержкой. Аналитический контур (планирование, отчёты, пояснения) может использовать LLM, но не совершает необратимых действий.
Всё общение через события с контрактом
Агенты не вызывают друг друга напрямую. Они публикуют версионированные события в общую шину. Агента можно заменить или перезапустить без правок соседей; обработка идемпотентна по event_id.
Молчание не значит «всё хорошо»
Нет данных, слепая зона, браслет снят, прогноз устарел: агент выдаёт явное состояние (unverified, no_signal, stale), а не пустоту. Отсутствие вывода не должно читаться как отсутствие проблемы.
Уверенность — часть данных
Каждая оценка несёт confidence и источник. Ниже порога оценка помечается needs_review: не отбрасывается молча и не подаётся как уверенный вывод.
Человек подтверждает необратимое
Запись плана во внешние системы, эвакуация, отправка отчёта надзору: только после подтверждения. Пока юристы не ответили по ст. 53 Строительного кодекса Дубая, автоматических действий по структурным рискам нет.
Дешёвый вход, дорогой анализ
По сводке операционные расходы на камеру около $13–45 в месяц, а оборудование отдельно. Поэтому пустые кадры отсекаем на edge, а в облако отправляем только то, что может изменить решение. предложение
Общие данные, не общая каша
Продукты читают один слой данных с площадки. Объединяются они только в A11 Fusion, и именно там действуют правила приватности: индивидуальное здоровье наружу не выходит, только агрегат по бригаде.

Схема цепочки

Слева направо: данные проходят защиту, превращаются в наблюдения, анализируются по продуктам, объединяются и доходят до людей. Нажмите на любой блок, чтобы увидеть вход, выход, логику, технологии и режимы отказа.

На схеме показаны основные потоки. Эталонная модель проекта (A1) и справочные данные читаются всеми агентами через шину и общее хранилище, поэтому линии от них не нарисованы. Полный список входов и выходов открывается по клику.

Основной алгоритм

Два режима работы. Долгие процессы ведёт оркестратор (workflow-движок). Реалтайм идёт хореографией: агенты реагируют на события в шине сами, центрального маршрутизатора на этом пути нет.

# 1. Долгие процессы: оркестратор A0 (workflow-движок)
workflow onboard_site(site):
    model = A1.parse(site.files)                       # график, смета → эталонная модель
    while model.open_questions:
        model = A1.resolve(ask_client(model.open_questions))
    wait_for(client.confirm(model))                    # ворота: без подтверждения мониторинг не стартует
    A2.apply_policy(site.jurisdiction, site.cameras)   # уведомления, основание, анонимизация, TTL
    A3.calibrate(site.cameras, model.zones)
    site.state = MONITORING

workflow daily_cycle(site, date):
    06:00  A14.digest(site, role=FOREMAN)              # вчерашний прогресс, материалы, риски дня
    day    stream_mode()                               # см. блок ниже, оркестратор не вмешивается
    18:00  A5.reconcile(site, date)                    # вечерняя сверка плана и факта
    18:30  A16.export_labels(site, date)               # подтверждения людей → разметка для калибровки

workflow weekly_cycle(site):
    A14.report(site, role=INVESTOR)                    # сводка, при подключении — данные Sustainability
    A14.report(site, role=SUPERVISION)

# 2. Реалтайм: хореография через шину (каждая строка — подписка агента)
on site.frame.sanitized  → A3.detect
on vision.detection      → A5.update_progress, A6.update_ledger, A9.crosscheck_if_crack
on progress.deviation    → A12.propose, A13.route
on weather.risk          → A12.propose, A11.join, A13.route
on worker.state          → A8.assess
on heat.risk(level ≥ warn)       → A13.route(worker, supervisor)
on sos | fall | no_motion        → A13.route(supervisor, ehs)       # минуя аналитику
on structure.risk                → A13.route(engineer, manager, require_ack=true)
on fusion.risk(level ≥ high)     → A12.propose, A13.route
on plan.approved                 → A15.write_back
on material.ledger               → A10.recalculate
on *                             → A16.record

# 3. Правила, общие для всех обработчиков
every handler:
    idempotent(event_id)
    if input.confidence < threshold: emit(needs_review)
    if source.silent > timeout:      emit(no_signal | stale | unverified)
    emit(output, causation_id=input.event_id)          # цепочка причин для аудита

Оркестратор нужен только там, где процесс долгий и ждёт человека. Если он упал, алерты продолжают идти по шине. Если замолчал критичный агент (A8, A9, A13), оркестратор переводит объект в состояние degraded и сообщает людям.

Как проверять качество

Теневой режим
Новая версия модели или порога работает параллельно, результаты сравниваются с текущей и с разметкой людей. В продуктив идёт после сравнения.
Выборка по каждому объекту
Качество Vision и Progress измеряем на размеченных кадрах конкретной площадки и климата, а не только на общих бенчмарках.
Разметка из работы
Каждое подтверждение или отклонение алерта человеком (A13, A16) становится меткой для калибровки порогов и моделей.
Целевые значения
Конкретные пороги точности и задержек определяем на пилоте. До него цифры были бы выдуманными; метрики по каждому агенту перечислены в его карточке.

Решения, которые нужны от технической команды

Часть вопросов взята из сводки, часть возникла при проектировании цепочки.

Критические элементы для пилота структурных рисков

Нужен перечень колонн и балок от структурного инженера. Без него A9 не с чего начинать.

Цены и форматы данных SHM-оборудования

Запросить у Sixense, Senceive, Worldsensing, Resensys цены и API. Адаптеры A9 зависят от форматов.

из сводки

HealthPulse: партнёр или своё устройство

Решение влияет только на слой адаптеров A4: интеграция с Kenzen или SlateSafety либо собственная прошивка и телеметрия. Остальная цепочка не меняется.

из сводки

Lynx Vision: SaaS или своё оборудование

SaaS проще для входа клиента, а hardware + SaaS даёт контроль качества данных, то есть качества входа для A3. Влияет на то, сколько обработки можно перенести на edge.

из сводки

Методология Sustainability

Источники данных о материалах, коэффициенты выбросов и владелец функции. Пока это не определено, A10 остаётся каркасом.

из сводки

Юридическая проверка авто-алертов

Применимость ст. 53 Строительного кодекса Дубая и вопрос ответственности. От ответа зависит, когда в A9 и A13 можно включить авто-эвакуацию.

из сводки

Где работает LLM и где хранятся данные

Видео и данные здоровья очень чувствительны. Нужно решить: собственное размещение или внешний API, и в какой юрисдикции хранятся данные клиентов. Проверить требования к локализации и трансграничной передаче.
